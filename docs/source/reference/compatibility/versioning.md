# 软件与契约版本

软件标识、契约版本和工程计划修订号独立。当前软件为 dev，`spec/1.0.0` 为开发契约草案。根 Python 元数据 0.0.0 代表开发工具，不是记录器或未来分析库的发行版；尚无批准的稳定发行、公开标签或项目许可。

## 软件标识规则

维护者批准的编号采用 SemVer，接口演进期间为 `0.MINOR.PATCH`，试用可用 `0.1.0-trial.1` 这样的 prerelease。1.0 前不兼容软件接口修改增加 MINOR，兼容修复增加 PATCH；1.0 需明确接口、支持和发行决定。这里的编号是规则示例，不是现存发行版。

构建可设置 `SLEDRA_VERSION`，允许字母、数字、点、加号和连字符；正式编号仍须遵循上述规则。构建器不强制 SemVer、不创建标签或发布。dev 本地产物可随输入更新，编号分发应保持不可变内容，字节改变应使用新标识。未来 `v<软件版本>` 标签需审查与发布批准，CI 目前不创建标签/发行版。

`SOURCE_DATE_EPOCH` 可设置 UTC 构建时间。`sledra --version` 分别记录软件、提交（含 dirty/unknown）、源码摘要、时间、Go、OS/架构和契约。未知元数据如实保留 unknown，不虚构。manifest 和 archive 校验和识别内容，不证明发布者身份。

## 兼容性与冻结输入

软件版本改变不授权事件/schema/身份改变。契约修改须遵循[来源审查](../contracts.md)、兼容向量、embed 同步及读写影响评估；草案编号不表示所有未来 1.x 行为均已实现。

M1.1 的 r 系列编号是工程计划修订，不是软件发行或契约升级。M2 先回放原 M1 输入并保留摘要；显式样本刷新需要审查、新旧摘要和 M2 输入再评估，见[工程交接](../../development/engineering-handoff.md)。普通测试不更新冻结证据。
